# Классификатор товаров по ПП № 1875 — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Веб-сервис, который по наименованию товара (или списку до 100) выдаёт код ОКПД2, режим по ПП № 1875, пункт постановления и уверенность; запускается `docker-compose up --build`.

**Architecture:** FastAPI + Celery/Redis + PostgreSQL/pgvector + React. Товар → эмбеддинг → top-20 кодов ОКПД2 из pgvector → кросс-энкодер выбирает код → детерминированный `matcher` сверяет код с позициями активной версии ПП. Модели локальные (CPU по умолчанию), LLM — опционально по ключу.

**Tech Stack:** Python 3.11, FastAPI, SQLAlchemy 2 + psycopg 3, pgvector, Celery 5 + Redis 7, sentence-transformers (torch CPU), openpyxl, python-docx, pdfplumber, httpx, pytest; React 18 + Vite + TypeScript + Mantine 7; nginx; PostgreSQL 16 (`pgvector/pgvector:pg16`).

**Spec:** `docs/superpowers/specs/2026-10-14-pp1875-classifier-design.md`

## Global Constraints

- Запуск: `docker-compose up --build` из корня, без ручных шагов и без интернета после сборки (веса моделей и индекс — в образе/репозитории).
- 1 запрос < 5 с; 100 товаров < 2 мин — на CPU.
- Лимит пакета — 100 товаров; больше → HTTP 422 с текстом «Не более 100 товаров за один запрос».
- Режимы (enum `Regime`): `ban` (ЗАПРЕТ), `restriction` (ОГРАНИЧЕНИЕ), `advantage` (ПРЕИМУЩЕСТВО), `none` (НЕ ПОДПАДАЕТ). Цвета UI: красный / жёлтый / синий / зелёный.
- Порог «⚠ проверьте вручную»: `confidence < 0.60` (`NEEDS_REVIEW_THRESHOLD`).
- Весь текст интерфейса и сообщений об ошибках — на русском.
- LLM включается только при непустом `LLM_API_KEY`; любой сбой LLM → локальный результат.
- Обновление НПА без передеплоя; новая версия становится активной только после успешного разбора.
- Тесты: `docker compose run --rm api pytest -q`. Тесты, грузящие модели, помечены `@pytest.mark.models`.
- Коммиты на русском, с строкой `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Excel «как у тендерника»**: шапка («Наименование», «№»), пустые строки, номера в первой колонке → берём первую колонку, где большинство значений — текст длиной ≥ 3, шапку пропускаем. (Тест — Task 8.)
2. **CSV из русского Excel**: кодировка cp1251 и разделитель `;` → читается так же, как UTF-8 c `,`. (Тест — Task 8.)
3. **Мусорный ввод** («asdf», «123», «-», 500 символов) → без падения, `needs_review=true`, пустые строки пропускаются с пометкой. (Тест — Task 6.)
4. **Код в нескольких приложениях / под исключением** → возвращаются все совпавшие позиции; исключение перекрывает родительскую позицию. (Тест — Task 4.)
5. **Дубли в пакете и порядок** → результаты в исходном порядке, дубли не пересчитываются. (Тест — Task 6.)

### Task 6: Реранкер, уверенность, конвейер и кэш

**Files:**
- Create: `backend/app/classifier/{reranker,confidence,pipeline}.py`, `backend/tests/classifier/{test_confidence,test_pipeline}.py`

**Interfaces:**
- Consumes: `normalize`, `Embedder`, `retrieve`, `match`, `verdict`, `get_active_items`, `get_active_version`.
- Produces:
  - `class Reranker: score(pairs: list[tuple[str, str]]) -> list[float]` (CrossEncoder, батч 32).
  - `to_confidence(scores: list[float], temperature: float) -> list[float]` — softmax по кандидатам с температурой; `CONFIDENCE_TEMPERATURE` в `Settings` (по умолчанию 1.0, подбирается в Task 7).
