# Фронтенд классификатора по ПП № 1875

React 18 + Vite + TypeScript, компоненты — [Mantine 7](https://mantine.dev). Внешний вид — по мотивам zakupki.gov.ru (ЕИС), где тендерные специалисты работают каждый день: синий `#0065dd`, текст `#334059`, серый фон `#eff0f2`, шрифт Roboto, плоские белые карточки (палитра — `src/theme.ts`, каркас страницы — `src/app.css`). Логотип и название ЕИС не используем — только стиль. Одна страница с двумя вкладками:
- **Проверка** — ввод товаров (строка = товар, до 100) или загрузка Excel/CSV → таблица: код ОКПД2, режим цветом и текстом, пункт ПП (клик — текст пункта), уверенность, «⚠ Проверьте вручную», раскрытие строки с объяснением, всеми пунктами и альтернативами, выгрузка. На телефоне (уже 48em) вместо таблицы — карточки с цветной полосой режима (`ResultCards.tsx`).
- **База НПА** — действующая редакция, загрузка новой (с паролем администратора), история редакций со статусами.

## Запуск

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173, работает на заглушках (бейдж «демо»)
npm run dev:api    # то же, но с реальным backend: /api → http://localhost:8000
npm test           # vitest
npm run build      # проверка типов + сборка в dist/
```

### В Docker (вместе с backend)

Из корня репозитория: `docker compose up --build` → сайт на **http://localhost:8080** (сервис `web`: сборка → nginx).
- nginx раздаёт SPA и проксирует `/api/` в `api:8000`; порт API наружу закрыт (`127.0.0.1:8000` — только Swagger на этом компьютере).
- Пока на backend нет API классификации, можно собрать сайт на заглушках: `VITE_USE_MOCKS=true docker compose up --build web`.
- В рабочей сборке заглушки вырезаются целиком (проверено: в бандле нет `mocks.ts`).
- Лимиты в `nginx.conf`: 10 запросов/с на API с одного адреса, пакет и загрузка НПА — 6 в минуту; файлы до 20 МБ; ответ API ждём до 300 с.
- Если сайт откроют через туннель (Cloudflare и т.п.), nginx видит адрес туннеля, а не пользователя — лимиты станут общими; настроить `real_ip` под туннель.

> Образ пока **не собирался в Docker** (на машине разработчика фронта его нет): проверена только сборка `npm ci && npm run build` в чистой копии и разбор `docker-compose.yml`. Первый `docker compose up --build` — на сервере или у backend-разработчика.

## Заглушки и контракт с backend

Пока на backend есть только `/api/health`, все вызовы идут в `src/mocks.ts` (`VITE_USE_MOCKS=true` в `.env.development`).
Заглушки отвечают по ключевым словам (ноутбук, бумага, щебень, халат, тумба, катетер, программа, лифт, хлеб) реальными позициями ПП из `data/npa/pp1875.json`; незнакомый товар даёт низкую уверенность. Пакет имитирует очередь (~150 мс на товар), новая редакция НПА «разбирается» 3 с.

Типы в `src/types.ts` повторяют `backend/app/schemas.py`. Эндпоинты — по плану (задачи 8–9):

| Вызов | Эндпоинт | Статус на backend |
|---|---|---|
| `getHealth` | `GET /api/health` | ✅ есть |
| `classify` | `POST /api/classify {name}` → `ClassificationResult` | ⏳ задача 8 |
| `classifyBatch` / `classifyFile` | `POST /api/classify/batch` (JSON `{names}` или multipart `file`) → `{job_id}` | ⏳ задача 8 |
| `getJob` | `GET /api/jobs/{id}` → `{status, total, done, results}` | ⏳ задача 8 |
| `jobExportUrl` | `GET /api/jobs/{id}/export.xlsx` | ⏳ задача 8 |
| `getNpaVersions` | `GET /api/npa/versions` | ⏳ задача 9 |
| `uploadNpa` | `POST /api/npa/upload` (multipart `file`, `title`, `source_url`) | ⏳ задача 9 |
| `getNpaItem` | `GET /api/npa/items/{id}` → позиция с `raw_text` | ⏳ задача 9 |

**Нужно согласовать с backend:**
- Пароль на загрузку НПА: фронт шлёт заголовок `X-Admin-Token` (сайт будет публичным, загрузка меняет базу для всех).
- Ответ об ошибке: фронт показывает `detail`, если это строка (так отдаёт FastAPI для `HTTPException`).
- Пока нет `export.xlsx`, кнопка выгрузки сохраняет CSV на стороне браузера (`src/exportCsv.ts`, те же колонки).
